# iOS app review, 1–2 November 2026

An automated multi-agent review of `ios/` (eight lenses, three rounds, every finding checked by three independent verifiers; 143 raw findings, 96 confirmed). Static reading plus live probing of the Python server: nothing was compiled or run on a device.

**Fixed** in the commits of 2 November: 31. **Open**: 65, listed with the reviewers' suggested fix.

## High (6)

### F01 · ✅ fixed · `ios/Fizzy/API.swift:147`

**download()/stream() discard the 423 body, so owner-gated requests loop on a numeric PIN prompt**

check() reads `need` from the 423 body and falls back to "pin"; download() (line 147) and stream() (line 174) pass `Data()`, so `{"need":"owner"}` is always treated as pin. Downloads default to owner level (pin.py downloads action) and Ask can be set to owner. The app shows the numeric PasscodeSheet, the PIN unlocks rank 1, the retry gets 423 owner again, forever; an owner password with letters cannot be typed on `.numberPad`.

### F12 · ✅ fixed · `ios/Fizzy/FizzyApp.swift:116`

**Passcode sheet is attached to RootView, so it cannot appear while a form sheet is presented**

`.sheet(item: $model.passcodeAsk)` lives on RootView, but most PIN-gated changes come from views already presented as sheets (Claim, Repay, Points, Tab, Restock, Payout, Assign, Edit...). Only one sheet per presentation context: the passcode sheet is deferred until the form sheet is dismissed while FormSheet shows a spinner with `.disabled(busy)` and no explanation; after Cancel the prompt appears and the retry completes on a dismissed sheet. Reasoned from code (no Xcode).

### F14 · ✅ fixed · `ios/Fizzy/Offline.swift:94`

**Queue and Page.submit infer the verdict from the session-global one-shot flash, which concurrent loads consume or misattribute**

After a POST, send() GETs /money and Page.submit reloads the page, reading `flash`. render() pops the flash on the first render of ANY page in the session, so any concurrent load (Dashboard 60 s timer, pull-to-refresh, ClaimSheet, and the queue's own `lastSent`-driven WaitingSection `.task(id: sent) { page.load() }` firing while the next item posts) steals a refusal: the queue sees no flash, announces 'sent.' and deletes the item and photo. Conversely a refusal from an unrelated form (repay, points, claim) landing in the slot is adopted as the restock's `problem` although it was saved; staff 'Delete it and add it again' creating a duplicate (fresh client_id). Page.submit returns `ok: flash?.ok ?? true` so absent flash looks saved.

### F59 · ✅ fixed · `ios/Fizzy/Components.swift:74`

**Page.submit derives the verdict from the reload, not the POST: a failed reload after a successful post reports failure (or offline, silent success with stale data), inviting double submits**

submit() posts, then load()s and returns `ok = flash?.ok ?? true`. If the POST is 303 but the reload fails non-offline (500/502/504), load() writes the error into flash and FormSheet shows 'Fizzy had a problem... Try again.' keeping the sheet open, so staff resubmit. If the reload fails offline, the cached pre-post copy is swapped in, flash stays nil, the sheet closes with no message and the list lacks the item, so staff re-enter it. Repayments, points, payouts and restock edits have no idempotency key; RestockSheet mints a fresh client_id per sheet.

### F61 · ✅ fixed · `ios/Fizzy/Offline.swift:81`

**Deleting a queued restock while send() is in flight still posts it (without its photo)**

send() iterates a value copy of `items`; while awaiting an upload the Delete swipe (not disabled while sending) calls remove(), deleting the photo and entry, but the snapshot still posts the item: server saves it with no receipt, remove is a no-op, lastSent says 'sent.' Auto-sends from connectivity/activation/timer mean the user can't know a send is running.

### F98 · ✅ fixed · `ios/Fizzy/ProfitView.swift:102`

**Profit cost fields go stale after refresh; Save then blanks and deletes inherited costs**

`costs` is filled only by fill() in the first .task and on range change; 'Get items from Square' and pull-to-refresh reload page.data without fill(). New keys (e.g. v:<variation> after a Square refresh) have no entry so the field is blank, and save() posts `costs[key] ?? ""` for every current row; server-side a blank where the cost was inherited from the plain name runs set_cost(None), removing the shared cost, while reporting 'Saved N cost(s).'
